# 食安哨兵 · 评分核心改造方案

> 场景定位：用户拍摄食品配料表 → 识别成分 → 对「该食品对当前用户的风险」给出可解释、可信、个性化的评估与解读。

---

## 一、改造背景与问题诊断

当前项目的 AI 能力集中在配料表 OCR 识别、食品分类与大模型报告生成，而**最核心的风险评分环节仍依赖人工固定规则**：

- 固定扣分：高风险扣 20、中风险扣 10、低风险扣 5（`RISK_PENALTY`）
- 固定人群倍率：儿童 ×1.2、孕妇 ×1.5、老人 ×1.3（`GROUP_PENALTY_RULES`）

这套逻辑存在三个根本缺陷：

1. **参数无数据依据**：20/10/5 与 1.2~1.5 均为人工拍脑袋，无法给出客观来源，经不起技术追问。
2. **静态、不可泛化**：对新出现的成分只能「查不到就不评」，无法适配复杂多变的真实配料表。
3. **把「客观成分风险」和「人群适配风险」揉在一个倍率里**，逻辑不清晰，也难以做到真正的个性化。

**本次改造不再迭代加减分规则，而是将评分核心整体升级为「知识图谱 + 表格基础模型 + 不确定性安全控制」的智能评估架构。**

---

## 二、改造目标

将评分核心从「人工规则打分」升级为「**专家知识 + 少样本泛化 + 安全管控**」的数据与知识双驱动体系：

- AI 深度参与「食品对当前用户风险有多大、为什么」这一核心判断；
- 保留法规规则作为刚性安全底线，不把安全完全交给模型；
- 新成分、证据不足等场景下主动拒判，保证食品安全场景的严谨性。

---

## 三、总体思路与核心定位

**一句话口径（答辩主叙事）：**

> 知识图谱存专家知识与标注 → 表格基础模型做少样本泛化 → 置信度门控做安全拒判 → 法规规则做硬兜底 → 大模型做个性化解释。

定位的关键原则：

- ❌ 不宣称「AI 自主学习风险、彻底替代人工」——表格基础模型是上下文学习模型，其知识上限取决于喂入的标注知识，这种说法经不起「标签从哪来」的追问。
- ✅ 诚实定位为「**专家标注知识做底座 + 表格基础模型做少样本泛化与一致性 + 不确定性管控做安全边界**」，既真实又更显专业。
- ❌ 不宣称「小样本下高精度」——现有数据无独立测试集，无法证明精度。
- ✅ 改述为「**一致、可泛化、可拒判**」。

---

## 四、整体架构

六层协同的混合智能决策架构：

```
┌─────────────────────────────────────────────────────────────┐
│ ① 知识底座   轻量领域知识图谱（替代「GraphRAG」重名词）         │
│             存专家知识与风险标注，是质量与可解释性的根本        │
├─────────────────────────────────────────────────────────────┤
│ ② 特征化     从图把每个 (成分 × 人群) 组合抽成特征向量         │
├─────────────────────────────────────────────────────────────┤
│ ③ 少样本预测 表格基础模型（TabICLv2 为主，TabPFN-3.5 对比）    │
│             以专家标注为上下文 → 新成分泛化 + 输出置信度        │
├─────────────────────────────────────────────────────────────┤
│ ④ 安全拒判   置信度 + 图内距离双重判定 → 低可信即拒判          │
├─────────────────────────────────────────────────────────────┤
│ ⑤ 法规兜底   forbidden_group 等硬约束，优先级最高、可覆盖模型   │
├─────────────────────────────────────────────────────────────┤
│ ⑥ 表达层     大模型（DeepSeek）把风险结果转成个性化人话解读     │
└─────────────────────────────────────────────────────────────┘
```

## 五、各模块详述（融合路径 / 核心逻辑 / 解决痛点 / 追问点）

### ① 知识底座：轻量领域知识图谱

- **融合路径**：以现有 CSV 结构化数据（`additives`、`group_warnings`、`beneficial_ingredients`、`avoid_options`）为骨架，由 DeepSeek 从 GB2760 / 权威文献抽取风险证据、法规限制、人群禁忌等补全，**人工复核**后入库。
- **数据结构**：
  - 节点：添加剂、类别、法规依据、风险证据、人群、禁忌场景；
  - 边：`属于→`、`禁忌于→`、`依据→`、`关联证据→`。
- **核心逻辑**：把「单字段查表匹配」升级为「多跳关系推理」，例如 `阿斯巴甜 → 含苯丙氨酸 → 苯丙酮尿症患者禁忌`，这是规则查表查不出来的链路。
- **解决痛点**：食品安全风险强关联、多维度耦合，单字段无法支撑精准研判。
- **追问点应对**：图的节点与边来源 = CSV 结构化 + LLM 抽取 + 人工复核；强调「知识构建」是真实工作量而非黑盒。

> 命名说明：不用正统 Microsoft「GraphRAG」（带社区检测/摘要，面向大规模异构文本），对 111 个添加剂的固定小图而言是过度设计。用「轻量领域知识图谱 + 图检索增强」，功能等价、更易落地、更可解释。

### ② 特征化

- **核心逻辑**：从图把每个 `(成分 × 人群)` 组合抽成固定维度的数值/类别特征向量——法规限制、风险证据强度、人群禁忌、食品品类等。
- **关键约束**：只使用「能真正获取」的特征，不引入「使用量/暴露量」（配料表只有成分顺序、无含量），避免被问死。

### ③ 少样本预测：表格基础模型

- **选型依据**：食品安全结构化数据少、标注样本稀缺，传统树模型（XGBoost/LightGBM）在小样本下易过拟合；表格基础模型为小样本表格数据而生，是当前 SOTA。
- **技术路线**：
  - 主模型：**TabICLv2**（ICML 2025 的 TabICL 升级版，开源宽松许可，落地成本低）；
  - 对比模型：**TabPFN-3.5**（Prior Labs 2026 年 9 月发布，Nature 论文谱系 SOTA）。
- **核心逻辑**：上下文学习——以专家标注的风险知识为上下文，对新成分做少样本泛化，同时输出风险置信度。
- **解决痛点**：新成分无法写死规则的问题；人工定级的一致性与可扩展性。
- **追问点应对**：诚实说明「标签 = 知识图谱里专家标注的风险等级」，模型做的是泛化 + 一致性 + 置信度，而非从零发现风险。

### ④ 安全拒判：不确定性评估

- **核心逻辑**：对模型输出做双重判定——① 模型置信度阈值；② 特征空间内与已知库的距离（异常检测）。低可信 / 超出已知范围即触发拒判，输出「证据不足、无法可靠判断、建议进一步核验」，而非强制给一个等级。
- **解决痛点**：通用 AI 强制输出的缺陷；食品安全零容错的行业要求。
- **追问点应对**：强调「拒判」不是靠单一 softmax 置信度，而是加独立异常检测，避免 in-context 模型对未见样本错误地高置信。

### ⑤ 法规兜底：规则硬约束

- **核心逻辑**：`forbidden_group` 等明确禁忌作为最高优先级硬约束，可直接覆盖模型输出。
- **定位**：AI 负责复杂隐性风险挖掘，法规规则守住刚性安全底线——「人机协同、合规兜底」。

### ⑥ 表达层：大模型个性化解读

- **核心逻辑**：DeepSeek 把「风险等级 + 主要风险因素 + 拒判理由」转化为通俗、个性化的用户分析报告，深度融入业务链路而非仅做文案。

## 六、完整技术路线

```
用户上传食品包装
  → 多模态 OCR 识别配料表
  → 食品成分解析与标准化
  → 融合成分风险特征 + 用户人群特征（知识图谱特征化）
  → 表格基础模型少样本预测（初始风险 + 置信度）
  → 知识图谱多维知识增强校验
  → 不确定性可信度评估
  → 分支判定：可信 → 输出风险等级 ／ 不可信 → 安全拒判
  → 法规安全约束兜底校验
  → 大模型生成个性化解读报告
  → 输出完整用户分析报告
```

---

## 七、核心创新点汇总

1. **小样本表格 AI 创新应用**：适配食品安全数据稀缺场景，以新一代表格基础模型替代人工规则，实现一致、可泛化的风险判定。
2. **领域知识图谱推理增强**：以知识检索与多跳推理替代单字段匹配，实现多维度立体研判。
3. **不确定性安全拒判机制**：赋予系统置信度自评能力，对未知/模糊场景主动拒判，贴合食安高安全需求。
4. **人群条件化风险评估**：取消人工固定倍率，融合人群特征实现千人千面的个性化研判。
5. **人机协同混合决策架构**：AI 负责隐性/非线性风险挖掘，法规规则负责刚性兜底，兼顾创新与合规。

## 八、与旧方案对比

| 维度 | 旧方案 | 新方案 |
| --- | --- | --- |
| 评分逻辑 | 固定加减分 + 固定倍率 | 知识 + 少样本泛化 + 安全管控 |
| 新成分处理 | 查不到就不评 | 少样本泛化 + 未知识别/拒判 |
| 人群差异化 | 固定倍率（主观、同质） | 条件化特征融合（千人千面） |
| 结果可信度 | 无 | 置信度评估 + 安全拒判 |
| 可解释性 | 规则数值，来源不明 | 知识图谱溯源 + 专家知识底座 |
| 安全性 | 全依赖规则 | 法规硬兜底 + 拒判双保险 |

## 九、关键技术选型与工程注意点

- **主模型 TabICLv2**：`pip install tabicl`，开源宽松许可，300~10 万样本、2000 特征均可覆盖；需 GPU 服务端推理。
- **对比模型 TabPFN-3.5**：`pip install tabpfn==9.0`，权重为非商用许可（商用需 Prior Labs API/license），作为技术对比与加分项。
- **知识存储**：轻量图可用 `networkx` / Neo4j + 向量检索实现多跳查询与图检索增强。
- **算力**：后端需 GPU 服务，答辩需说明「服务端 GPU 推理」的部署方案。

## 十、风险与应对

1. **标签闭环**：表格模型是上下文学习，标签来自知识图谱的专家标注——本方案已诚实定位为「专家知识 + 少样本泛化」，规避「自主学习」的不实宣称。
2. **特征可得性**：仅使用可获取的特征，不引入「使用量/暴露量」等无数据维度。
3. **图构建成本**：知识图谱构建是真实工作量，采用 CSV 结构化 + LLM 抽取 + 人工复核的分级策略控制成本。
4. **技术堆砌**：明确主次——核心创新聚焦「知识图谱 + 少样本泛化」两项做深，其余作为保障机制。
