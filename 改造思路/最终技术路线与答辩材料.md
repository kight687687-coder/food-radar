# 食安哨兵 · 评分核心改造：最终技术路线与答辩材料

> 本文档是 Phase 1–5 全部落地实施后的**最终版**技术路线与答辩材料，记录实际架构、真实评测数字与关键决策。事前设计见《评分核心改造方案.md》，两者偏差在第六节诚实说明。
>
> **一句话口径（答辩主叙事）：**
> 知识图谱存专家知识与标注 → 表格基础模型做少样本泛化 → 置信度门控做安全拒判 → 法规规则做硬兜底 → 大模型只做解释不改决策。

## 一、最终技术路线（落地架构）

### 1.1 运行时决策顺序（六层架构落地版）

```
输入 (成分, 人群)
  │
  ├─ ④-1 库外成分？ ──────────是→ 拒判 unknown「成分不在知识库中」
  ├─ ④-2 无效人群？ ──────────是→ 拒判 unknown「人群不在九大类内」
  │
  ├─ ⑤ 法规兜底（最高优先级硬约束）
  │     forbidden_for 边命中 → R1 证据复核（label_rules.py，与标签校准同一口径）
  │     仅「明确禁用」(ban_high：多国已禁用/婴儿食品禁用映射儿童/
  │     苯丙酮尿症患者禁用映射儿童+孕妇) → 覆盖为 high, source=regulatory
  │     限制/慎用/亚人群作用域外 → 不覆盖，交模型层
  │
  ├─ ③ TabICLv2 少样本泛化（990 对全量专家标注作 in-context 上下文）
  │     46 维特征 → 预测 medium/low 边界 + 置信度
  │
  ├─ ④-3 安全门控
  │     confidence < 0.75 或 OOD 距离 > d99 阈值 → 拒判 unknown（证据不足）
  │
  └─ ⑥ 表达层（explain.py）
        决策字段逐位透传，绝不修改
        explanation_chain ← 知识图谱多跳链路
        narrative ← DeepSeek 个性化人话解读（不可用自动回退确定性模板）
```

### 1.2 四条工程铁律（贯穿全部阶段）

| 铁律 | 落地方式 |
| --- | --- |
| **防标签泄漏** | risk_level / forbidden_for 是标签不进特征；beneficial_to_group 不进风险模型（标签语义泄漏）；warns 只作证据强度序数 |
| **宁缺勿滥** | 图谱抽取只保留明确支持的关系；无证据链时保持空节点/空边；库外成分不编造解释链 |
| **标签口径单一事实源** | label_rules.py 同时服务「标签校准」与「运行时兜底」，两者永远一致（修复了 csv forbidden_group 与人工确认口径冲突的 bug） |
| **表达层不改决策** | risk_level / source / confidence / explanation_chain 逐位透传；DeepSeek 故障静默回退模板；单元测试断言「解释前后决策字段逐位一致」 |

### 1.3 核心代码结构

```
backend/
├── knowledge_graph.py      # ① 图谱 + 多跳解释链检索 find_explanation_chains
├── features.py             # ② 46 维特征 + 按成分分组&分层的评测划分
├── tabicl_input.py          # ③ 990 对标签加载（kg_labels_final.csv）
├── label_rules.py           # ⑤ R1 证据复核规则（标签校准与运行时兜底共用）
```

## 二、五阶段实施记录

### Phase 1 · 知识图谱构建（知识底座）

- CSV 结构化骨架 + DeepSeek 证据抽取（GB2760 / 权威文献）+ 人工复核分级入图（P0 含法规限制 / P1 模型新增节点边 / P2 仅 suggestive / P3 空抽取）。
- **产出**：图谱 **218 节点 / 519 边**；110 个成分的证据复核 JSON 全部入图；典型多跳链路如「阿斯巴甜 →含苯丙氨酸→ 苯丙酮尿症患者禁忌」「亚硝酸钠 →转化为→ 亚硝胺风险证据」。
- 每个成分节点带 evidence_features（regulatory_restriction / special_population_related / risk_statement_exists / evidence_strength 三档）。

### Phase 2 · 特征工程 + 标签生成

- **46 维特征**：成分侧 26 维（证据强度序数、法规限制、类别 one-hot×20、天然/营养/合成来源、证据密度等）+ 交互侧 5 维（warns 关联强度、多跳链路可达性）+ 人群侧 9 维（九大人群 one-hot）。
- known/unknown 成分**同构**（库外成分也有默认向量，只是被门控拒判，而非走另一套逻辑）。
- **标签 990 对**（110 成分 × 9 人群）：法规约束 + 图谱证据 + risk_level 初始值 + 自动校准 + 人工确认。
  - 分布：**high 28 / medium 242 / low 720**（high 仅来自 4 个极高风险成分）。
  - 与旧规则 baseline 一致率 95.5%（45 差异对逐条复核，接受了亚硝酸钠/糖精钠×孕妇降级等，阿斯巴甜按确认口径保持人群条件化标签）。
  - 关键修正：区分「明确禁用」（ban_high）与「限制/注意」（降级 medium），亚人群禁忌不向普通人群扩散。
- **产出**：`kg_labels_final.csv`、`kg/label_review_report.md`（含 P0/P1/P2 复核明细与人工确认记录）。

### Phase 3 → 3.5 · 评测与特征优化

- 评测协议：**按成分分组留出**（同成分 9 对不跨 train/test）+ **risk_level 分层**（每档至少留 1 成分），多 seed（42/7/2026）。
- Phase 3（39 维）：accuracy 3-seed 均值 **84.7%**（多数类基线 72.7%）。暴露问题：天然色素 36 对假阳性、磷酸 9 对假阴性（特征区分度不足）。
- Phase 3.5（+7 维：natural_source / nutrient_related / synthetic_origin / evidence_density / evidence_count / risk_relation_count / population_relation_count）：
  - **accuracy 91.6%（+7pp），macro F1 0.603**；上述旧错误清零；新增三氯蔗糖/纽甜 18 对假阳性（synthetic_origin 副作用，净收益显著）。
  - **high recall 0%** → 架构性结论：high 是 4 个成分的极小类，in-context 泛化不是它的职责 → **high 由⑤层法规兜底负责**，模型只管 medium/low 边界泛化。这是六层架构分工的直接证据。
- 拒判调参：OOD 阈值 d95 过紧（误拒正确样本）→ 放宽 **d99**（训练集 LOO 距离分位数）；confidence 阈值 **0.75**。

### Phase 4 · 集成预测器（六层合体）

- `risk_predictor.py`：库外拒判 → 法规兜底（R1 复核）→ TabICLv2 批推理 → confidence+OOD 双门控 → 附多跳解释链。
- **全库端到端验证：99.9% 一致（989/990）**
  - 法规兜底 7 对全部 high 且与标签一致；
  - 模型分支 982 对 100% 与专家标签一致；
  - 唯一拒判：糖精钠×孕妇（confidence 0.57 < 0.75，真实标签 medium）——**诚实拒判而非强制分类**。
- TabICLv2 权重本地化（105.3MB），CPU 推理可用，fit 一次约 60–90 秒后进程内复用。

### Phase 5 · 表达层 + API（本次交付）

- `explain.py`：`build_explanation` 决策字段透传 + `template_narrative` 三类确定性模板 + `narrate_explanations` DeepSeek 批量个性化解读（失败静默回退，永不影响风险结论）。
- 输出字段（确认口径）：**risk_level / source / confidence / explanation_chain / reject_reason**（非拒判为 null），另附 reason 与 narrative。
- 真实端到端冒烟（TabICLv2 全管线 + DeepSeek 真实调用）四分支全部正确，决策隔离断言通过。
- 测试：**25 个新测试 + 全量 120 passed**。
- API 接入：见下节。

## 五、答辩 Q&A（追问点应对）

**Q1：标签从哪来？模型不是自己学会判断风险的吧？**
> 诚实定位：标签 = 法规约束 + 知识图谱证据 + risk_level 初始值 + 人工校准（990 对，审核报告可查）。TabICLv2 是上下文学习模型，做的是**泛化、一致性与置信度**，不是从零发现风险。全库端到端 99.9% 一致率证明模型忠实复现专家口径并在新样本上平滑泛化。

**Q2：为什么用表格基础模型而不是 XGBoost？**
> 食品安全结构化数据少（990 对）、类别不均衡（high 仅 28 对），传统树模型小样本易过拟合；TabICLv2 是小样本表格 SOTA，不训练直接 in-context 推理，天然输出置信度支持拒判。

**Q3：high 类 recall 是 0%，模型不准？**
> 恰是架构设计的证据：high 是 4 个成分的极小类，硬交给 in-context 泛化不可靠，所以架构上由⑤层法规兜底 100% 负责（端到端验证兜底 7 对全对）。模型只负责 medium/low 边界——各司其职，这正是「不把安全完全交给模型」的落地。

**Q4：怎么防止模型对没见过的成分瞎猜？**
> 双重门控：softmax 置信度 < 0.75 拒判；特征空间 OOD 距离（z-score + kNN，阈值取训练集 LOO 距离 d99 分位）超界拒判；库外成分直接拒判。拒判输出「证据不足」而非强制等级——食品安全零容错。

**Q5：LLM 会不会改坏风险结论？**
> 表达层与决策层物理隔离：DeepSeek 只接收判定结果生成 narrative，代码上只能覆写 narrative 字段；单元测试断言「解释前后 risk_level/source/confidence 逐位一致」；DeepSeek 故障自动回退确定性模板，永不阻塞风险结论输出。

**Q6：新旧规则差异怎么处理？**
> 45 个差异对逐条复核：区分「明确禁用」与「限制/注意」（后者不判 high）；亚人群禁忌不向普通人群扩散（如糖精钠禁忌源是婴儿食品禁用，不映射孕妇）；阿斯巴甜保留「风险随人群条件变化」设计。label_rules.py 单一事实源保证标签与运行时兜底永远同口径。

**Q7：为什么不叫 GraphRAG？**
> 111 个添加剂的固定小图，正统 GraphRAG（社区检测+摘要）是过度设计。「轻量领域知识图谱 + 多跳链路检索」功能等价、更易落地、可解释。

**Q8：为什么不迁 FastAPI？**
> 现有服务是 Flask 且旧接口（/analyze 等）已被前端依赖；迁移框架与「保持旧接口兼容」目标冲突。新增 /api/v2/risk 端点、旧端点零改动是兼容成本最低的方案。

## 六、与最初方案的偏差与取舍（诚实记录）

| 原方案设想 | 实际落地 | 原因 |
| --- | --- | --- |
| TabPFN-3.5 对比模型 | 未做 | TabICLv2 单模型已达标（91.6%），对比实验非核心创新，时间花在特征优化上 |
| 需 GPU 服务端推理 | CPU 推理可用 | TabICLv2 990 样本 in-context 规模小，CPU fit 60–90s 后单例复用，本地/Vercel 均可跑 |
| GraphRAG 命名 | 轻量领域知识图谱 | 避免过度设计与名词堆砌 |
| 表达层「深度融入业务链路」 | 表达层严格只读（决策隔离） | 落地中发现"LLM 参与判定"经不起安全追问，收敛为「只解释不改决策」，反而成为答辩亮点 |
| 旧标签规则做初始值 | 旧规则仅作 baseline 对比 | 避免模型学旧规则而非图谱证据模式（45 差异对就是价值所在） |

## 七、演示脚本建议（5 分钟）

1. **拒判演示**（最出彩）：输入一个编造成分「二甲基二硫代氨基甲酸锌XYZ」→ 系统诚实拒判并给出原因「成分不在知识库中」——对比通用 AI 强行回答。
2. **法规兜底**：苋菜红 × 儿童 → high，reason 引用「多国已禁用」，explanation_chain 显示图谱链路。
3. **多跳推理**：阿斯巴甜 × 儿童 → high，链路「阿斯巴甜 →含苯丙氨酸→ 苯丙酮尿症患者禁忌」——查表规则给不出的链路。
4. **人群条件化**：同一成分切换人群（阿斯巴甜：儿童 high / 普通人群 medium）→ 千人千面。
5. **诚实拒判**：糖精钠 × 孕妇 → confidence 0.57 拒判 → 「宁缺勿滥」价值观。
6. **接口兼容**：旧 /analyze 照常工作，新 /api/v2/risk 并存。
