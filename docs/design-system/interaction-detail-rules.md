# 食安哨兵细节与交互质感规则

本文档定义食安哨兵微信小程序的第四层设计规则：分割线、列表对齐和基础微交互。

关联文档：

- `docs/design-system/information-architecture.md`
- `docs/design-system/component-detail-rules.md`

## 1. 目标

第四层优化不改变页面职责和信息架构，只用于提升精致度、可扫读性和触感稳定性。

目标：

- 分割线使用有规则。
- 图标、文字、状态、箭头对齐稳定。
- 点击反馈可预测。
- 避免复杂动画造成小程序卡顿。

关键原则：

> 能用留白解决的，不用线；能用基础反馈解决的，不做复杂转场。

## 2. 分割线规则

分割线只用于卡片内部同类条目之间，不用于替代模块间距。

### fr-divider-full

用途：

- 卡片内部大块内容分组。
- 需要完整横向分隔的场景。

规则：

- 颜色使用 `#F2F3F5`。
- 高度 `1rpx`。
- 不用于页面大模块之间。

### fr-divider-inset

用途：

- 列表行之间。
- 左侧缩进对齐文本起点，而不是对齐图标。

规则：

- 颜色使用 `#F2F3F5`。
- 高度 `1rpx`。
- 左侧缩进由具体列表图标宽度和 gap 决定。

### fr-divider-soft

用途：

- 卡片内部轻量信息分组。
- 主信息和辅助说明之间。

规则：

- 颜色使用 `rgba(229, 231, 235, 0.72)`。
- 不抢视觉权重。

## 3. 分割线禁止事项

禁止：

- 为了“精致”在每个模块之间加线。
- 卡片之间使用分割线替代留白。
- 同一列表中有的条目有线、有的条目无规则无线。
- 使用深色分割线制造后台表格感。

## 4. 列表对齐规则

列表行使用统一结构，避免每个页面临时写 margin 和 flex。

推荐结构：

```text
fr-list-row
  fr-list-icon
  fr-list-main
    fr-list-title
    fr-list-desc
  fr-list-meta
  fr-list-arrow
```

### fr-list-row

用途：

- 最近记录。
- 重点关注。
- 设置项。
- 管理入口。

规则：

- 使用 grid 或 flex 保证图标、文本、右侧状态稳定对齐。
- `align-items: center`。
- 主文本区域必须 `min-width: 0`，确保长文本省略。

### fr-list-icon

用途：

- 列表左侧图标容器。

规则：

- 使用全局 icon-box 规则。
- 不在单个页面私自放大缩小。

### fr-list-main

用途：

- 标题和说明文字容器。

规则：

- `min-width: 0`。
- 标题和说明组成文本组，不靠零散 margin 临时调位置。

### fr-list-meta

用途：

- 分数、状态、时间、标签。

规则：

- `flex-shrink: 0`。
- 右对齐或居中由具体场景决定。
- 不应抢主标题权重。

### fr-list-arrow

用途：

- 可进入详情的列表项。

规则：

- 使用 neutral 弱色。
- 不应比主信息更醒目。

## 5. 微交互规则

微交互只分两档，避免真机上不可感知的过度细分。

### fr-press-strong

适用：

- 主按钮。
- 图标入口。
- 明确的强操作。

规则：

```css
transform: scale(.96);
opacity: .88;
```

### fr-press-light

适用：

- 卡片。
- 列表行。
- 普通入口。

规则：

```css
transform: scale(.985);
opacity: .94;
```

### 过渡规则

所有 press 类统一使用：

```css
transition: transform .14s ease, opacity .14s ease, background-color .14s ease;
```

## 6. 动画限制

允许：

- 页面主卡轻微 `fade + translateY`。
- 列表项点击反馈。
- 按钮点击反馈。
- 识别任务中的必要动效。

禁止：

- 复杂页面转场。
- 大量卡片同时入场动画。
- 每个入口都有独立动画。
- 为普通页面加持续运动装饰。

## 7. 执行顺序

第四层按以下顺序执行：

```text
0. app.wxss
   写好 divider / list / press 基础类，但不挂载页面。

1. 首页
   最近识别、常用功能接入统一点击反馈和列表结构。

2. 扫描页
   上传建议、最近识别、PK 卡接入统一列表和反馈。

3. 档案页
   下一步建议、重点关注、最近记录接入统一 list-row 和 inset divider。

4. 其它页面
   逐步收敛，不一次性大面积替换。
```

## 8. 检查清单

每次做第四层优化前检查：

- 这里是否真的需要分割线？
- 如果需要，应该是 full、inset 还是 soft？
- 分割线左侧是否对齐文本起点？
- 图标、标题、说明、右侧状态是否使用统一列表结构？
- 长文本是否有 `min-width: 0` 和省略策略？
- 点击反馈应该是 strong 还是 light？
- 是否出现了复杂转场或过度动效？
- 是否只是为了“看起来精致”而增加视觉元素？

## 9. 总结

第四层质感来自细节一致，而不是更多线条和动画。

最终判断标准：

```text
列表对齐稳定，
分割线有理由，
点击反馈可预测，
动画少而必要。
```
