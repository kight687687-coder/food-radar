# 食安哨兵信息架构与信息流规则

本文档定义食安哨兵微信小程序的页面职责、信息层级、跨页面数据流和组件强度规则。后续页面改版、组件精修、功能新增都应先按本文档检查，避免不同页面重复承担同一职责。

## 1. 产品核心原则

食安哨兵不是后台报表，也不是纯工具箱。它的核心体验是：帮助家庭理解食品安全状态，并在合适的时刻推动用户完成识别、查看原因、调整选择。

核心原则：

- 首页讲立即行动。
- 识别页产生数据。
- 结果页解释单次食品。
- 档案页讲长期理解。
- 探索页提供知识与工具。
- 我的页管理身份与偏好。

关键判断：

> 先定义每个页面为什么存在，再决定它应该展示什么。

## 2. 底部 Tab 页面职责

### 首页

回答的问题：

- 现在家庭食品安全状态怎么样？
- 我是否需要马上识别一次食品？

核心内容：

- 家庭安全指数。
- 当前状态。
- 立即扫描入口。
- 最近识别的轻量回顾。

不承担：

- 周/月/年趋势分析。
- 长期风险画像。
- 复杂管理入口。

### 识别

回答的问题：

- 我如何上传食品、配料表或包装图？
- 当前识别任务进行到哪一步？

核心内容：

- 上传入口。
- 识别能力说明。
- 最近识别入口。

不承担：

- 家庭长期状态判断。
- 趋势分析。
- 账户与家庭设置。

### 档案

回答的问题：

- 为什么现在是这个状态？
- 最近是否变好或变差？
- 接下来应该怎么做？

核心内容：

- 近 7 天安全指数。
- 与上周对比。
- 主要原因。
- 建议。
- 重点关注。
- 最近记录作为证据。

不承担：

- 首页式强行动入口。
- 工具箱式功能集合。
- 过重的管理入口。

### 探索

回答的问题：

- 我想主动查食品知识、添加剂、配料表或使用工具，应该去哪？

核心内容：

- 添加剂百科。
- 配料表对比。
- AI 问答。
- 食品知识与工具。

不承担：

- 家庭安全指数展示。
- 当前成员健康状态判断。

### 我的

回答的问题：

- 我是谁？
- 我管理哪些家庭成员、偏好和设置？

核心内容：

- 当前用户。
- 家庭成员。
- 偏好设置。
- 系统设置。

不承担：

- 安全指数主展示。
- 食品结果解释。
- 趋势分析。

## 3. 信息层级规则

每个页面的信息都应按 L1-L5 分层。页面可以包含多个层级，但每个一级页面最多只能有一个 L1。

### L1 页面主判断

页面最核心的信息，每页最多一个。

示例：

- 首页：家庭安全指数。
- 结果页：本次食品评分。
- 档案页：近 7 天安全指数与趋势。

规则：

- L1 必须第一眼可见。
- L1 不应被入口卡、装饰图、管理功能抢视觉权重。
- L1 不能在同一页面被图形和文字重复放大表达。

### L2 核心解释

解释 L1 为什么成立。

示例：

- 主要原因。
- 风险成分。
- 建议。
- 趋势变化。

规则：

- L2 应紧跟 L1。
- L2 使用用户语言，不使用后台字段感文案。
- L2 优先解释原因和影响，而不是堆指标。

### L3 下一步操作

用户看完 L1/L2 后可以做什么。

示例：

- 立即扫描。
- 继续识别。
- 查看高频添加剂。
- 更新忌口偏好。

规则：

- 操作必须服务当前页面职责。
- 首页可以强化主行动。
- 档案页的行动应温和，避免任务打卡感。

### L4 证据与记录

支撑判断的信息，不是主角。

示例：

- 最近记录。
- 近 7 天出现次数。
- 历史食品列表。
- 识别时间。

规则：

- L4 应用于建立可信度。
- L4 不应抢 L1 的视觉中心。
- 列表内容要稳定、可扫读、对齐清楚。

### L5 管理与补充

低频入口和设置类信息。

示例：

- 家庭成员管理。
- 风险偏好。
- 设置。
- 档案管理入口。

规则：

- L5 默认放在页面靠后位置。
- L5 不应使用强主卡样式。
- L5 不应承担页面核心解释。

## 4. 跨页面信息流

一次食品识别产生的信息只能沿一条主链路流动，避免页面各自重新解释同一数据。

主信息链：

```text
识别一次食品
→ 生成本次食品评分（结果页 L1）
→ 写入识别记录（档案页 L4 来源）
→ 更新家庭安全指数（首页 L1 来源）
→ 累计进入近7天趋势（档案页 L2 来源）
→ 长期积累形成风险画像（档案二级页长期视图）
```

页面职责对应：

- 识别页：产生识别记录。
- 结果页：解释本次食品。
- 首页：概括当前家庭状态。
- 档案页：解释趋势、原因和下一步建议。
- 探索页：提供知识解释与工具。
- 我的页：管理成员和偏好。

规则：

- 首页和档案页可以使用同一套基础记录，但表达粒度不同。
- 结果页不能把单次食品评分叫作家庭安全指数。
- 档案页不能凭空生成与首页不一致的整体状态。
- 记录、指数、趋势、画像必须有明确的数据来源关系。

## 5. 指标命名规则

同一指标跨页面必须使用稳定命名，避免用户混淆。

### 家庭安全指数

使用场景：

- 首页 L1。

含义：

- 当前家庭或当前成员的整体食品安全状态概括。

不用于：

- 单次食品结果。
- 长期画像。

### 本次食品评分

使用场景：

- 结果页 L1。

含义：

- 用户本次识别食品的评分与判断。

不用于：

- 首页。
- 档案页主趋势。

### 近7天安全指数

使用场景：

- 档案页 L1。

含义：

- 当前成员近 7 天识别记录形成的阶段性状态。

必须配套：

- 与上周对比。
- 主要原因。
- 建议。

### 风险画像

使用场景：

- 档案二级页或档案页低权重区域。

含义：

- 基于长期记录形成的倾向判断。

规则：

- 数据不足时不默认强展示。
- 必须说明依据，例如“基于近 30 条识别记录生成”。

## 6. 组件强度规则

组件不只按颜色分类，还要按语义与强度分类。

### 强度等级

weak：

- 浅底色 + 深色文字。
- 用于辅助信息、普通标签、轻提醒。

medium：

- 浅底色 + 更高字重或更明确边界。
- 用于当前状态、重点标签、页面内关键解释。

strong：

- 实色底 + 白色文字，或强主按钮。
- 只用于主行动、高风险警示、关键结果。

### 语义颜色

success：

- 安全、稳定、正常、已完成。

warning：

- 轻度关注、近期风险、需要留意。

danger：

- 高风险、禁忌、严重警示。

info：

- 数据、趋势、工具、普通信息。

ai：

- AI、画像、个性化建议。

neutral：

- 等待、未生成、普通说明。

推荐命名方式：

```text
success-weak
success-medium
warning-weak
warning-medium
danger-medium
danger-strong
info-weak
ai-weak
neutral-weak
```

## 7. 例外机制

设计系统不是所有元素完全一样，而是 80% 统一 + 20% 可控例外。

允许例外的场景：

### 首页主行动

首页的“立即扫描”可以比普通按钮更突出，因为首页职责是推动行动。

限制：

- 只能突出一个主行动。
- 不应让其它入口抢同等视觉权重。

### 识别页任务态

上传、识别中、识别成功可以使用更强视觉反馈，因为识别页是任务流程页。

限制：

- 强反馈只服务流程状态。
- 不扩展到普通功能入口。

### 高风险结果

结果页遇到禁忌、高风险或严重提醒时，可以使用更强警示样式。

限制：

- 必须有明确风险依据。
- 不应用于普通轻提醒。

默认不允许例外：

- 档案页不允许强运营感。
- 探索页不允许过多彩色入口同时抢权重。
- 我的页不允许展示过多健康结论。

## 8. 禁止事项

以下规则用于防止页面后续改版重新变乱。

1. 不要多个一级页面重复承担同一职责。

   例如：首页、档案页、我的页都展示同样的安全指数。

2. 不要用图形重复表达已有数字。

   例如：页面已经有 75 分，就不要再放一个同等权重的 75 分仪表盘。

3. 不要让管理入口抢核心内容。

   档案管理、家庭成员、偏好设置属于 L5，不应使用主卡权重。

4. 不要在一级页面出现周/月/年切换器。

   一级页面负责快速理解与行动，不承担复杂分析。周/月/年切换应放入饮食趋势、健康报告等二级页面。

5. 不要把标签颜色当成唯一语义。

   标签必须同时定义语义和强度，例如 warning-weak、danger-strong。

6. 不要让装饰图形成为页面主视觉。

   图形必须服务信息表达；如果只重复数字或制造噪音，应删除或降级。

7. 不要在页面首屏堆多个同级卡片。

   首屏应优先保证 L1 和 L2 清晰，不应同时出现多个视觉中心。

## 9. 页面检查清单

每次新增或改版页面前，按以下问题检查：

- 这个页面回答的核心问题是什么？
- 页面 L1 是什么？是否只有一个？
- L2 是否解释了 L1，而不是重复 L1？
- 用户看完后下一步能做什么？
- 哪些信息只是证据，是否被放在 L4？
- 管理入口是否被降级到 L5？
- 是否有跨页面指标命名不一致？
- 是否破坏了主信息链？
- 是否出现了不该有的周/月/年切换？
- 是否有图形重复表达已有数字？

## 10. 当前产品方向总结

食安哨兵的高级感不来自更多装饰，而来自页面职责清晰、信息流稳定、判断链路完整。

最终目标：

```text
识别页产生数据，
结果页解释单次，
首页概括当前，
档案页解释变化，
探索页提供知识，
我的页管理身份。
```

这条规则优先级高于单个组件样式。
