# 快速体验中心设计

## 目标

将现有 `/examples` 页面扩展为轻量的快速体验中心：用户可以直接打开三款真实食品示例、查看一组固定 PK 结果，并进入 AI 营养师和添加剂百科，同时保留上传真实配料表的入口。

## 体验结构

1. **示例食品**：保留小烤肠、安慕希酸奶、冰红茶三张真实图片。点击后沿用现有示例分析结果与动态转场。
2. **配料表 PK**：增加一个紧凑区域，展示小烤肠与冰红茶两张真实图片。点击后将两款本地固定分析结果预置到现有 `/compare` 页面，自动进入可查看结果的 PK 状态，不调用 OCR、AI 接口或写入历史。
3. **更多工具**：提供两个小入口，分别跳转 `/ai-chat` 和 `/wiki`。百科入口展示“150+ 种添加剂百科”文案，实际数量由百科页面数据源呈现。
4. **真实使用**：保留“上传自己的配料表”入口并放在页面下方。

## 约束

- 沿用现有 Web 版视觉、卡片、间距和移动端布局。
- 快速体验页只展示必要内容，不在首页展开完整 PK 报告。
- PK 示例使用本地预置结果，现场网络异常时仍可打开结果页。
- 既有真实上传 PK 和单品扫描流程保持不变。
- 示例 PK 不新增历史记录。

## 交互与错误处理

- 点击 PK 示例时先写入一个一次性 compare preset，再导航到 `/compare`。
- `/compare` 识别 preset 后直接显示两款食品与结果；消费后清理 preset，刷新页面不会重复注入。
- 若 preset 数据缺失，现有空状态和上传流程继续工作。
- AI 营养师、百科入口复用现有路由，不复制页面逻辑。

## 验证标准

- `/examples` 桌面端显示三张单品卡、一个 PK 区域、两个工具入口和上传入口。
- 移动端内容单列、图片完整显示、按钮文字不溢出。
- 点击 PK 能看到小烤肠 vs 冰红茶的评分、风险差异和 AI 对比建议。
- 单品示例、真实上传、AI 营养师和百科入口行为不回归。
