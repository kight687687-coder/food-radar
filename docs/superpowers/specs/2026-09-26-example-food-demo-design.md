# 示例食品快速体验设计

## 背景

线上 Web 版第一次访问会先进入健康档案页。用户可以点击“暂时跳过”进入首页，但首页当前主要依赖用户上传自己的配料表图片。比赛评委或普通新用户可能暂时没有食品实物，因此需要一个不依赖实物和现场 OCR 的快速体验入口。

本设计在保留现有健康档案流程、真实图片上传流程、页面视觉和 AI 分析动效的前提下，增加一个通用的“快速体验”入口。它面向所有新用户，不使用“评委演示”等专用文案。

## 目标

- 保留首次访问的健康档案页和“暂时跳过”行为。
- 在首页增加一个占用空间很小的“快速体验”入口。
- 提供一个简洁的“示例食品”选择页，只展示三张真实食品图片。
- 选择样例后使用固定分析结果，复用现有结果页和 AI 分析转场。
- 让体验不依赖现场网络、OCR 服务或 AI 服务。
- 保持真实上传配料表的原有流程和业务含义不变。

## 非目标

- 不新增评委专用模式或比赛专用入口。
- 不修改健康评分、风险匹配、OCR 或 AI 报告算法。
- 不在示例页展示全部样例库、分类筛选或复杂搜索。
- 不把示例分析写入用户的扫描历史。
- 不重新设计现有页面视觉语言或动效体系。

## 用户流程

### 首次访问

1. 用户打开网站，进入现有“健康档案”页面。
2. 用户填写档案，或点击现有“暂时跳过”。
3. 跳过逻辑继续创建默认的“我自己 / 普通人群”档案，并进入现有首页。

### 快速体验

1. 首页现有“拍照识别配料表”主操作下方增加次级入口“快速体验”。
2. 用户点击后进入“示例食品”页面。
3. 页面展示三张推荐样例：小烤肠、安慕希酸奶、冰红茶。
4. 用户点击任意样例卡片或“开始体验”按钮。
5. 系统载入该样例的固定结果，进入现有食品分析结果页。
6. 结果页继续播放现有 AI 分析引导和阶段动效，随后保持完整结果展开。
7. 用户可以返回“示例食品”，也可以进入“上传自己的配料表”流程。

### 真实扫描

用户从首页主按钮或示例页底部入口上传自己的图片时，继续使用现有图片预处理、OCR、后端分析、结果保存和历史记录流程。

## 页面设计

### 首页入口

在现有首页的“拍照识别配料表”主按钮附近放置小型次级按钮或文字链接：

```text
拍照识别配料表

      ✦ 快速体验
```

入口沿用现有颜色、字体、圆角、间距和图标规则。它需要有明确文字，不能只使用图标。入口不新增大面积卡片，避免改变首页信息层级。

### 示例食品页

页面沿用现有 `Page`、卡片和返回导航样式，标题和说明为：

- 标题：`示例食品`
- 副标题：`选择一款，查看完整食品安全分析`

页面只展示三张卡片，不提供全部样例列表、分类筛选或搜索。每张卡片包含：

- 真实食品图片；
- 食品名称；
- 食品类别；
- 简短说明；
- “开始体验”操作。

推荐样例：

| 样例 ID | 名称 | 类别 | 展示方向 |
| --- | --- | --- | --- |
| `xiaokaochang` | 小烤肠 | 肉制品 | 添加剂和风险项识别 |
| `anmuxi-yogurt` | 安慕希酸奶 | 乳制品 | 配料、营养和人群建议 |
| `ice-black-tea` | 冰红茶 | 饮料 | 饮料类配料和风险提示 |

卡片整体可点击，按钮用于强化可操作性。页面底部增加轻量入口“上传自己的配料表”，跳转到现有 `/scan` 页面。

### 结果页

示例选择复用现有 `ResultPage`，不创建第二套结果页。结果页增加轻量的“示例分析”标识，以及返回示例页的入口。现有评分区、食品图片、风险项、有益成分、忌口提示、AI 分析阶段、AI 营养师入口和操作按钮继续沿用。

示例结果完成展示后不写入 `memberHistory` 或其他扫描历史数据，避免用户的个人记录被样例污染。示例页返回和真实扫描返回的行为保持清晰可辨。

## 动效和状态

- 示例选择后复用现有 AI 分析引导弹窗和 `AiAnalysisStages` 阶段组件。
- 阶段顺序保持当前产品顺序：识别配料、发现风险和有益信息、生成判断、给出建议。
- 总体播放保持在数秒内，完成后所有阶段继续展开。
- 不新增独立的“评委演示”动画或特殊视觉主题。
- 遵循现有 `prefers-reduced-motion` 行为，减少动效时仍展示完整内容。

## 数据设计

在 Web 前端增加一个本地示例注册表。每个样例包含：

```text
id
name
category
imageSrc
description
result
```

`result` 使用现有结果页能够消费的结构化字段，至少包括：

```text
food_category
ingredients
ingredients_count
health_score
risk_additives
beneficial_ingredients
avoid_warnings
group_warnings
ai_report
```

三张真实图片放置在：

```text
web/public/images/demo/xiaokaochang.jpg
web/public/images/demo/anmuxi-yogurt.jpg
web/public/images/demo/ice-black-tea.jpg
```

示例结果完全在本地注册表中读取，不触发 OCR、AI 分析或后端网络请求。真实上传图片仍调用现有分析接口。

## 可靠性和错误处理

- 示例页加载不依赖后端可用性。
- 示例数据缺失时，页面返回示例列表并显示可操作的提示，不进入空白结果页。
- 示例图片加载失败时使用现有图片占位样式，卡片仍保留名称和操作反馈。
- 用户刷新结果页时，示例上下文可以根据样例 ID重新解析，不依赖临时网络响应。
- 示例结果不写入扫描历史，也不改变家庭成员的真实统计。

## 响应式和可访问性

- 手机端三张卡片按单列排列，保证图片、名称和按钮不溢出。
- 桌面端可以使用两列或三列卡片布局，保持页面最大宽度和现有内容区域一致。
- 图片提供有意义的替代文本。
- 卡片和按钮具备键盘焦点状态，整卡点击不会隐藏独立按钮的语义。
- 返回、开始体验和上传入口使用清晰的中文可访问名称。

## 验收标准

- 清除浏览器存储后访问根路径，仍然先出现健康档案页。
- 点击“暂时跳过”后进入原首页。
- 首页能看到小型“快速体验”入口，且不遮挡现有主扫描按钮。
- 点击入口进入“示例食品”页，只看到小烤肠、安慕希酸奶、冰红茶三张样例卡片。
- 三张卡片使用真实图片，名称和类别正确。
- 点击任一样例能进入对应结果页，现有 AI 分析动效按原样播放。
- 三种样例结果内容互不混淆，页面显示“示例分析”标识。
- 示例结果不会出现在扫描历史和最近识别记录中。
- 示例页的“上传自己的配料表”仍能进入真实扫描流程。
- 在无后端或网络不稳定时，示例体验仍能完成。
- Web 生产构建、现有测试和移动端窄屏检查通过。

## 实施顺序

1. 将三张真实食品图片复制到 `web/public/images/demo/` 并确认尺寸和清晰度。
2. 增加本地示例注册表和固定结果数据。
3. 增加示例食品页路由和卡片页面。
4. 在首页增加“快速体验”次级入口。
5. 让结果页识别示例上下文并显示标识，复用现有动效。
6. 验证示例不污染历史，确认真实上传流程不受影响。
